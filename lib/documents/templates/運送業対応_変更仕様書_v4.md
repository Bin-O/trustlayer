## 設計の中核思想（v4で明文化）

### 入れるのは条文ではなく判定ルール

法令そのものを検索できるようにしても価値はない（e-Govで無料）。
本製品が行うのは、**法令から「この人・この事業所に、いま、どの義務がかかるか」を導くこと**。
ただし各判定ルールは必ず条文に紐づけ、根拠を示せる状態にする（`legal_basis`）。

### 絞り込みの鍵は「作業プロファイル」

「職種・作業内容に応じて該当する義務だけを出す」ことが目的だが、
その作業内容をどう取得するかが最大の設計課題である。

- 細かく入力させる → 使われない
- 粗くしか取らない → 全員に全部表示されるのと同じ

**解：人ごとに20項目程度の はい/いいえ を持つ「作業プロファイル」**（第12章）。

### 範囲は「手元のデータで判定できるもの」に限る

労働安全衛生法は巨大であり、全体を実装することはできない。

| 入れる | 入れない |
|---|---|
| 資格 × 作業の照合 | 作業環境測定（測定値を保有しない） |
| 健診の周期（配属情報から導ける） | リスクアセスメントの実施品質 |
| 選任義務（事業所の人数・作業から導ける） | 機械の個別点検状況 |

判定できないものを「対応済」にも「未対応」にもしない。
該当の可能性があれば**「要確認」**として提示する（5.2）。
対象：TrustLayer
目的：自動車運送業分野の義務に対応する。あわせて、業界義務のハードコードを
　　　データ（義務マスタ）へ移行し、以後の分野追加を「設定」で行えるようにする。

## 想定顧客（v2で追加）

- 全国に支店を持つ物流会社
- 外国人材の在留資格：特定技能・自動車運送業分野
- **同一人物が「トラック運転」と「倉庫内の荷役作業」の両方に従事する**
- → 運転系の義務（道路運送法系）と荷役系の義務（労安法系）が
　　 **同じ人に同時にかかる**。これが本案件の設計上の要点。

## 1. 背景

### 1.1 なぜ運送業か
- 実在の顧客企業が1社あり、現場の声を聞ける
- 建設業と並ぶ優先分野
- 分野固有の義務が多く、「業界特化」の実証に適している

### 1.2 なぜ義務マスタを同時に作るか

運送業の義務は12項目前後あり、うち4つの類型は**現在のシステム構造では表現できない**。

| 類型 | 運送業での例 | 現状 |
|---|---|---|
| 企業レベルの義務 | 認証取得、協議会加入 | 雇用関係が主キーのため置き場所がない |
| 事件型 | 事故惹起運転者への特別な指導 | 発火パターンが存在しない |
| 閾値監視型 | 時間外労働 年960時間上限 | 期限がないため義務として扱えない |
| 免除条件付き | 過去3年の運転者経験で初任教育免除 | 「要確認」状態が存在しない |

これらをハードコードで追加すると、現在2分野分のハードコードが
一気に増え、次の建設業で同じ作業を繰り返すことになる。
**運送業を義務マスタの最初の実装対象とし、製造業は移行して構造を検証する。**

### 2.1 テーブル `obligations`（規則マスタ）

```

-- 期限

                            --  '前提義務の完了日' '年度末'
```

### 2.2 `trigger_condition` の形式（JSONB）

発火パターンごとに必要なパラメータが異なるため JSONB とする。

```json
// 時限型
{"type":"time", "from":"入社日", "days":0, "before":true}

// 資格型
{"type":"qualification", "work":"フォークリフト運転", "required":"技能講習修了"}

// 継続状態型
{"type":"duration_state", "state":"未就労", "from":"許可日", "days":30}

// 事件型
{"type":"event", "event":"事故惹起"}

// 閾値監視型（※義務マスタ外で扱う。6.4参照）
```

**制約**：JSONB の中身を解釈するコードは必要なため、
「新しい発火パターン」を増やすときはコード変更が要る。
ただし **同じパターンの義務を追加するだけならデータ投入で済む**。
この妥協を許容する。

### 2.2.1 主体は3層（v4で変更）

v3では `worker` / `company` の2層としていたが、
労安法の資格表を精査した結果、**第3の主体が必要**であることが判明した。

| 主体 | 意味 | 例 |
|---|---|---|
| `worker` | その人が満たす必要がある | フォークリフト運転者（技能講習） |
| `establishment` | **その作業現場／事業所で満たす必要がある** | **はい作業主任者の選任**、事業所の産業分類、認証の保有 |
| `company` | 法人として満たす必要がある | 協議会加入 |

**`establishment` が必要な理由**：
労安法の「○○**作業主任者**」は、個人が資格を持てばよいのではなく、
**その作業ごとに有資格者を選任し、職務を行わせる義務**である。
「誰か1人が資格を持っている」では要件を満たさない。

資格一覧の中で、`role` が「○○作業主任者」で終わるものは
すべて `establishment` の選任義務として扱う。
「○○作業者」「○○運転者」は `worker` の資格要件。

多拠点対応（第9章）の事業所マスタと同じ主体を使う。

### 2.3 テーブル `obligation_instances`（判定結果）

```
id
obligation_id / obligation_version   -- どの規則のどの版に基づくか
subject_type                          -- 'worker' / 'company'
subject_id
status                                -- 未対応 / 対応済 / 対象外 / 要確認
deadline_date                         -- 算出された期限
deadline_exception_date               -- 例外期限（ある場合）
progress_current / progress_required / progress_unit
                                      -- 積み上げ型（例：座学 8/15 時間）
completed_at
evidence_type / evidence_id           -- ★完了の根拠（記録の存在）
exempted_reason
computed_at
input_snapshot                        -- JSONB。判定時の入力データ
prev_hash / hash                      -- 将来の改ざん防止用。当面 NULL
```

**`evidence_*` は必須設計**。完了状態は「記録が存在すること」で証明する。
「完了にする」ボタンで緑にできる経路を作らない。
判定結果が人為的に緩められない構造にしておくことは、
将来の人材紹介事業との利益相反を構造で防ぐための前提でもある。

#### 3.1.1 認証の正確な内容（運用要領 第3-4(4)）

| 区分 | 認められる認証 |
|---|---|
| トラック | 運転者職場環境良好度認証（一般財団法人日本海事協会）**又は** 安全性優良事業所＝Gマーク（全国貨物自動車運送適正化事業実施機関） |
| タクシー・バス | 運転者職場環境良好度認証のみ（**Gマークの選択肢なし**） |

#### 3.1.2 ★重要：事業所の産業分類要件（運用要領 第3-4(3)）

> 特定技能雇用契約に基づいて1号特定技能外国人がその活動を行う
> 特定技能所属機関の**事業所**は、日本標準産業分類に掲げる産業のうち、
> 次のいずれかに掲げるものを行っていることとする。
> **43 道路旅客運送業／44 道路貨物運送業**

**倉庫業は産業分類47であり、この要件を満たさない。**

多拠点の物流会社では、支店ごとに産業分類が異なり得る。
純粋な倉庫事業所へ配属・転勤させると事業所要件を満たさなくなる可能性がある。

→ **事業所マスタに日本標準産業分類を保持する必要がある**（第9章）。
→ 支店間異動には2つの判定が同時にかかる：
　 ①随時届出（14日以内） ②異動先事業所の産業分類が43/44か

**手続順序**：認証取得 → 協議会加入申請 → 証明書受領（約1ヶ月）→ 在留資格申請
この順序自体を画面で示す必要がある（後述 5.1）。

#### ★★ 健康診断の周期は年1回とは限らない（既存実装のバグ候補）

**特定業務従事者の健康診断（安衛則45条）**：

> 深夜業などの特定業務に常時従事する労働者に対し、
> **その業務への配置替えの際**及び**6ヵ月以内ごとに1回**、定期に実施する

特定業務（安衛則45条・イ〜ワ）のうち本案件に該当し得るもの：

- **ヌ 深夜業を含む業務** ← **トラック運転者はほぼ該当する**
- **ト 重量物の取扱い等重激な業務** ← 荷役作業

→ **この顧客の従業員は健診が年2回である可能性が高い。**

**要確認（既存実装）**：雇用条件書の「初回の定期健康診断（その後○ごとに実施）」欄と、
システムの健診リマインダーが年1回前提になっていないか（第7章 #15）。

「配置替えの際」は**イベント型**の発火であり、下記の通り転勤と連動する。

### 3.4 荷役作業（倉庫内作業）— v2で追加

在留資格上の業務区分は「自動車運送業」でも、実際の業務には倉庫内の荷役が含まれる。
**この乖離が見えていないことが、本製品が解決する問題そのもの**
（ピッチP4のフォークリフトの事例と同一構造）。

#### 3.4.1 資格型（作業割当 × 資格保有）

既存の判定エンジンがそのまま適用できる。作業マスタに荷役系を追加するだけ。

**データソース**：`anzen_shikaku_master.csv`（109件・根拠条文付き）。
`logistics_relevant = True` の26件が物流関連。これを義務マスタへ投入する。

主なもの（`subject_type` 付き）：

| code | 作業 | 要件 | 主体 | 根拠 |
|---|---|---|---|---|
| `CARGO_FORKLIFT` | フォークリフト運転 | 最大荷重1t以上→技能講習／1t未満→特別教育 | worker | 安衛令20(11)／安衛則36(5) |
| `CARGO_TAMAKAKE` | 玉掛け | 1t以上→技能講習／1t未満→特別教育 | worker | 安衛令20(16)／安衛則36(19) |
| `CARGO_TAILGATE` | **テールゲートリフター操作** | **特別教育**（学科4h＋実技2h）**2024年2月1日〜** | worker | 安衛則 |
| `CARGO_SHOVEL_LOADER` | ショベルローダー等運転 | 1t以上→技能講習／1t未満→特別教育 | worker | 安衛令20(13)／安衛則36(5-2) |

#### ★ はい作業主任者について

> 高さが**2m以上**のはいのはい付け又ははいくずしの作業
> （荷役機械の運転者のみによって行われるものを除く）→ 技能講習修了者

**物流倉庫で2m以上に積まないことはまずない。** にもかかわらず
「はい作業主任者」を選任している倉庫は多くない。

フォークリフトは「資格が要る」と広く認識されているが、
「積み上げるだけ」で主任者の選任が要るとは思われていない。
**フォークリフトより発見されにくい義務**であり、
顧客に見せたときのインパクトが大きい。

**`CARGO_TAILGATE` の詳細**
- 学科4時間（リフターの知識1.5h／作業の知識2h／関係法令0.5h）＋実技2時間
  → **積み上げ型**（初任運転者教育と同じ構造）
- 6か月以上の業務経験者などは一部省略可 → **免除条件あり＝「要確認」状態が必要**
- 記録は**3年間保存** → 前提義務つきの記録保存義務
- 作業開始前点検の義務あり（安衛則第151条の75）→ 継続義務

#### 3.4.2 設備・着用義務（2023年10月1日 対象拡大）

| 義務 | 対象 | 備考 |
|---|---|---|
| 昇降設備の設置 | 従来5t以上 → **2t以上5t未満も対象** | 車両に紐づく |
| 保護帽の着用 | 従来5t以上 → **2t以上5t未満で荷台側面が開放・開閉できる車両（平ボディ車・ウイング車）およびテールゲートリフター設置車も対象** | 作業×車両の組合せ |

**設計判断（要検討）**：これらは「人」でも「会社」でもなく**車両**に紐づく。

- 案A：`subject_type` に `vehicle` を追加し、車両台帳を持つ
- 案B：車両台帳は持たず、荷役作業の割当時のチェック項目として扱う

**本仕様書では案Bを採用する。**車両管理に踏み込むと運行管理システムの領域となり、
製品の焦点がぼやけるため。ただし顧客が車両台帳を求める可能性があるため、
訪問時の確認項目とする（第7章）。

- 陸上貨物運送事業における荷役作業の安全対策ガイドライン

## 3.6 業務範囲の判定（v2で追加・重要）

### 3.6.1 なぜ必要か

在留期限の管理だけでは不十分で、**「この人はこの作業をしてよいのか」**を
判定する必要がある。これは資格保有の判定とは**別の法律**の問題である。

| チェック | 問い | 法律 | 実装状況 |
|---|---|---|---|
| ① 資格保有 | 必要な資格を持っているか | 労働安全衛生法 | 実装済 |
| ② 業務範囲 | 在留資格の範囲内の作業か | 入管法 | **未実装** |
| ③ 主従バランス | 関連業務に偏っていないか | 入管法 | **未実装** |

①と②は**同じ瞬間（作業割当時）に発生する、別々の違反リスク**である。
③は期限ではなく比率を監視するため、閾値監視型として扱う（6.4と同系統）。

### 3.6.2 自動車運送業の業務範囲（一次資料で確認済み）

国土交通省「制度概要」による主な業務内容：

| 区分 | 主な業務内容 |
|---|---|
| **トラック** | ①運行業務　**②荷役業務** |
| タクシー | ①運行業務　②接遇業務 |
| バス | ①運行業務　②接遇業務 |

**荷役業務が主たる業務に含まれるのはトラックのみ。**

#### 関連業務の扱い（運用要領 第3-1）

> 当該業務に従事する日本人が通常従事することとなる関連業務
> （例：車両の清掃など試験等によって専門性を確認されない業務）に
> **付随的に**従事することは差し支えない

**重要な訂正**：
「専ら関連業務に従事することは認められない」という文言は、
**分野別運用要領には存在しない**。あるのは「付随的に」という限定のみ。
当該文言は全分野共通の運用要領側にあるため、
判定ロジックの根拠条文としてどちらを引くかを実装前に確定すること（第7章 #11）。

#### 本案件における論点

トラック運転者の荷役は主たる業務に含まれるため、**荷役そのものは適法**。

ただし運用要領の「荷役業務」が
「自車への積付け」を指すのか「倉庫内作業全般」を含むのかは明示されていない。
実態が「運転者として在留しているが大半は倉庫内の一般作業」であれば、
業務区分違反のリスクが残る。

これはピッチP4のフォークリフト事例と同一構造の事故だが、
**違反する法律が異なる**（労安法ではなく入管法）。

### 3.6.4 特定活動期間中の業務範囲（運用要領 第3-3）

> 当該在留資格による在留中には、上記手続等のほか、受入れ機関における
> **車両の清掃といった関連作業**に従事することを認める

特定活動（外免切替・研修期間）中に認められるのは
**車両の清掃等の関連作業のみ**であり、荷役業務は含まれない。

期間はトラック最大6か月、タクシー・バス最大12か月。
**この期間中に倉庫作業に従事させると資格外活動となる。**

→ 在留資格が「特定活動」の間は、作業割当のチェックを
　 特定技能1号より厳しくする必要がある。

### 3.6.3 設計方針

- **業務範囲マスタ**：在留資格 × 分野 × 業務区分 → 各作業の扱い
  （主たる業務／関連業務／不可）を保持する
- 全在留資格に適用する。例：
  - 技術・人文知識・国際業務 → 現場作業は原則不可
  - 資格外活動（留学生） → 週28時間の上限
  - 身分系（永住者・定住者等） → 制限なし
- 作業割当時に①資格保有と②業務範囲の両方を判定する
- ③主従バランスは作業実績の比率から監視する

**この機能が「在留資格を横断する」という立ち位置の実体となる。**
在留期限管理はどの競合もやっているが、
業務範囲の判定は在留資格ごとの制度理解がないと作れない。

### 3.5 特定活動（準備期間）固有

運用要領 第3-3 で確認済み。

| 項目 | 内容 |

## 9. 多拠点対応（v2で追加）

全国に支店を持つ顧客を想定するため、以下が必要になる。

| 本社俯瞰ビュー | 全拠点のコンプライアンス状況を本社が一覧する画面 |

## 12. 作業プロファイル（v4で追加・設計の要）

### 12.1 目的

「職種・作業内容に応じて該当する義務だけを出す」ための入力。
人ごとに**20項目程度の はい/いいえ**を保持し、
これが労安法・入管法**両方の判定を同時に駆動する**。

### 12.2 項目例（物流会社の場合）

```
運転系
  □ トラックを運転する（最大積載量：___t）
  □ 深夜業を含む
  □ 旅客を運送する（タクシー／バス）

荷役系
  □ フォークリフトに乗る（最大荷重 1t以上／1t未満）
  □ 2m以上に積む（はい付け・はいくずし）
  □ 玉掛けをする（1t以上／1t未満）
  □ テールゲートリフターを操作する
  □ ショベルローダー等を運転する
  □ 不整地運搬車を運転する
  □ 重量物を扱う

その他
  □ 倉庫内作業の比率（概算）
  □ 配属事業所
```

### 12.3 一度の入力が2つの法律を駆動する

| 入力 | 労安法が言うこと | 入管法が言うこと |
|---|---|---|
| フォークリフトに乗る | 1t以上なら技能講習が必要 | — |
| 2m以上に積む | **はい作業主任者の選任**が必要（事業所） | — |
| 深夜業を含む | 健診は6ヶ月ごと | — |
| 最大積載量2t以上で荷役 | 昇降設備・保護帽 | — |
| 倉庫作業の比率が高い | — | 業務区分の範囲を超える懸念（3.6） |
| 配置替えがあった | 特定業務なら健診（安衛則45条） | 随時届出＋事業所の産業分類（3.1.2） |

ピッチP5「二重入力ゼロ ── 一度入れた情報は全帳票・全判定に再利用される」の実体。

### 12.4 職種テンプレート

職種ごとにプロファイルの初期値を持つ。
例：「トラック運転者（荷役あり）」を選べば20項目が埋まり、違う箇所だけ直す。

これが「専門家を雇ったような体験」の入口側。
専門家は空白のフォームを渡さず、「御社は製造業で月給制ですね、
ではこの辺りは通常こうです」と埋めてから差分だけ確認する。

### 12.5 配置替え＝1つの出来事に3つの法律

転勤・配属変更が発生したとき、同時に3つの判定が走る：

| # | 判定 | 法律 |
|---|---|---|
| 1 | 随時届出（14日以内） | 入管法 |
| 2 | 異動先事業所の産業分類は43/44か | 入管法 |
| 3 | 特定業務への配置替えなら健康診断 | 労安法 |

そのまま画面にしたもの。** 実在顧客で発生し得る。
